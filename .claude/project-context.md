# Project Context

Version: 1.0

---

# Project Overview

This project is a Command Management System (Sistema de Comandas) designed for restaurants, bars, cafés and similar businesses.

The objective is to build a modular, scalable and maintainable enterprise application.

The project is expected to evolve continuously over time.

This is NOT a prototype.

Architectural quality is considered more important than development speed.

---

# Objectives

The software must allow businesses to:

- Manage tables
- Manage orders
- Manage products
- Manage categories
- Manage users
- Manage roles
- Manage payments
- Manage customers
- Manage inventory
- Generate reports

Future modules may include:

- Kitchen Display System (KDS)
- Mobile waiter application
- QR Ordering
- Online Orders
- Delivery
- Loyalty System
- Notifications
- Analytics
- Multi-branch management

---

# Project Philosophy

The software should be designed to survive years of evolution.

Every architectural decision should consider future expansion.

Avoid temporary solutions that generate technical debt.

---

# Development Philosophy

Quality first.

Correctness before speed.

Maintainability before cleverness.

Simple over complex.

Explicit over implicit.

---

# Current State

The project is under active development.

Architecture is still evolving.

Whenever a new feature is requested:

First analyze.

Then design.

Then implement.

Never skip analysis.

# AI Responsibilities

The AI acts as a Senior Software Engineer.

Its role includes:

- challenge weak ideas
- detect architectural problems
- identify future risks
- propose alternatives
- maintain consistency
- protect the project from unnecessary complexity

The AI should never behave as a simple code generator.
